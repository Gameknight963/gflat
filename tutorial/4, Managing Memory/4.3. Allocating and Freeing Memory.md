# Allocating and Freeing Memory

Sometimes, you might want an array of a dynamic size, or to return a unique pointer on each function call.

<details>
<summary>The stack and the heap</summary>

We can do that by allocating memory on the heap.

Many programming languages don’t require you to think about the stack and the heap very often. But in a systems programming language like G♭, whether something is on the stack or the heap affects what you do with that memory.

Both the stack and the heap are "memory," but they are structured in different ways.

The stack is managed as functions are called and return. It's like our stack of books from eariler: you can stack books on top of each other, and remove them in the opposite order. This is referred to as last in, first out (LIFO).

The heap is less organized: you request memory from an allocator, and it gives you memory... somewhere.

The stack grows downwards on our supported targets.

Using the stack is generally faster than using the heap. Reserving stack space usually takes only a few CPU instructions. Allocating memory is significantly more complicated. This is one reason why _allocation free_ libraries are championed in C and C++ (the other being they are much more portable).

The downside is that a stack buffer does not grow when you write past its end. Making it "larger" would just mean overwriting whatver is above/below it. The heap is better suited for something that must grow and shrink at runtime (such as a Vector), which can allocate a larger block when needed.

</details>
<br>

Take this example for instance:

Filename: static_storage.gf
```cpp
int* GetPointer()
{
    static int number = 4;
    return &number;
}

int main()
{
    int* ptr1 = GetPointer();
    *ptr1 = 777;
    int* ptr2 = GetPointer();
    Console::WriteLine(*ptr1);
    Console::WriteLine(*ptr2);
    return 0;
}
```

```
$ gfc static_storage.gf --run
777
777
```

The pointee of `ptr2` changed when we dereferenced `ptr1`! That's because we returned the address of the same static variable, so they point to the same location in memory.

To fix this, we can _allocate memory_ on the heap. That can be done with `Memory::Allocate()`. It returns `void*?`, so we need to cast it before using it:

```cpp
int* GetPointer()
{
    return ((int*?)Memory::Allocate((nuint)sizeof(int)))!;
}

int main()
{
    int* ptr1 = GetPointer();
    *ptr1 = 777;
    int* ptr2 = GetPointer();
    Console::WriteLine(*ptr1);
    Console::WriteLine(*ptr2);
    return 0;
}
```

```
$ gfc allocation.gf --run
777
0
```

Why was the second one zero? Well, we never set the memory in that allocation to anything, so it's whatever was there before. The OS wipes pages before giving them to you if they were used by another process previously for security reasons, so that could be one reason why it was 0. Reading uninitialized memory like this is undefined behavior, so this output is not guaranteed.

This is also technically bad practice. If `Allocate()` returns null, that means the allocation failed. You should always check:

```cpp
int*? GetPointer()
{
    return (int*?)Memory::Allocate((nuint)sizeof(int));
}

int main()
{
    int*? ptr1 = GetPointer();
    if (ptr1 == null) return 1;
    *ptr1 = 777;
    int*? ptr2 = GetPointer();
    if (ptr2 == null) return 1;
    *ptr2 = 0;
    Console::WriteLine(*ptr1);
    Console::WriteLine(*ptr2);
    return 0;
}
```

Later, we'll learn about exceptions, which can make code like this less repetitive.

This memory is also...

## Leaking.

Any memory allocated MUST be freed with `Memory::Free()`! Otherwise you get a _memory leak_: your program uses more and more memory until bad things happen (depending on your OS).

In this case, it's technically fine. We make two allocations before immediately exiting. The exit means the OS cleans any memory we allocated anyway.

But it's good practice to free the memory regardless:

```cpp
using Standard;

int*? GetPointer()
{
    return (int*?)Memory::Allocate((nuint)sizeof(int));
}

int main()
{
    int*? ptr1 = GetPointer();
    if (ptr1 == null) return 1;
    *ptr1 = 777;
    int*? ptr2 = GetPointer();
    if (ptr2 == null)
    {
        Memory::Free(ptr1);
        return 1;
    }
    *ptr2 = 0;
    Console::WriteLine(*ptr1);
    Console::WriteLine(*ptr2);
    Memory::Free(ptr1);
    Memory::Free(ptr2);
    return 0;
}
```

Note that `ptr1` and `ptr2` are dangling after freeing them. Dereferencing them is undefined behavior, and will probably crash your program.
