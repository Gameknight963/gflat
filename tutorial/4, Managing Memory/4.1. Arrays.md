# Arrays

The array is the simplest data structure.

You might recall from section 3.4 that strings are simply an array of characters.

Filename: arrays.gf

```cpp
int main()
{
    readonly(char)* string = "hello!";
    Console::WriteLine(string[0]);
    return 0;
}
```

```
$ gfc arrays.gf --run
h
```

Let's break down what's going on here:

```cpp
readonly(char)* string = "hello!";
```

This is a _pointer_ to the first element of the array. We'll discuss pointers in more detail in section 4.2, but just know that it "points" to the first element of the array. So that's the first character of the string, or `'h'`.

```cpp
string[0]
```

Square brackets "`[]`" are the _index_ operator. The number passed inside of them represents what index of the array we want. Arrays are zero-indexed in G♭, so `string[0]` represents the first element of the array.

`"hello!"` is 6 characters. So what happens if we try to read `string[6]` (the seventh element)?

```cpp
int main()
{
    readonly(char)* string = "hello!";
    Console::WriteLine(string[6]);
    return 0;
}
```

```
$ gfc arrays.gf --run

$
```

That makes sense. The string is actually _seven_ bytes, not six, due to the null terminator signifying the end of the string. Let's read `string[7]` then:

```cpp
int main()
{
    readonly(char)* string = "hello!";
    Console::WriteLine(string[7]);
    return 0;
}
```

```
$ gfc arrays.gf --run

$
```

...huh??

### Undefined behavior

Reading out-of-bounds of an array is an example of _undefined behavior_. That means anything might happen, the language doesn't make any guarantees.

In this case, there may have been a zero byte at that memory address. That translates to the NUL character, which, obviously, doesn't show up as anything. What is stored beyond the array is not guaranteed.

Although it's very unlikely in this specific case, we could've also read into _unmapped memory_, which is memory that hasn't been allocated yet. Here's what that would've looked like:

```
$ gfc arrays.gf --run
Segmentation fault (core dumped)
```

A segmentation fault most commonly happens when we read unmapped memory, or try to dereference a null pointer.

By default, the OS forcefully terminates your program when this happens.

> Yes I know SEH exists. G♭ doesn’t support it currently.

This is why it is probably a good idea to use the `Standard::Collections` types instead of a native array, since they provide bounds-checked access.

The "(core dumped)" part means the OS attempted to save a core dump file. If saved, it includes several things that might help you debug the crash:

 - Some or all of your program’s memory at the point of the crash
 - CPU register values
 - What caused the crash (in our case, SIGSEGV)

 You can use a tool like `gdb` to read core dumps, but it's genuinely painful. Handling memory is quite dangerous.

 I don't think fsanitize is supported currently so if you get a memory bug god help you.

 ## Declaring arrays manually

 Using a string as an array is sometimes useful, but in the vast majority of cases, you'll want to use your own arrays.

 In section 4.3, we'll learn about allocating memory on the heap and how to put arrays there. For now, we'll just use stack buffers,which are easy to use.

> This section may have factual inaccuracies surronding the initialization of arrays.

Filename: arrays.gf

```cpp
int main()
{
    int[] array = [1, 6, -3];
    Console::WriteLine(array[0]);
    Console::WriteLine(array[1]);
    Console::WriteLine(array[2]);
    return 0;
}
```

```
$ gfc arrays.gf --run
1
6
-3
```

Let's break down that first line where we create an array:

```cpp
    int[] array
```

This creates an array named 'array'. The array is a _stack buffer_. We'll talk more about the stack and the heap in section 4.3, but the relevant part is that it's size must be known at compile time.

```cpp
[1, 6, -3];
```

This initializes the array with the values 1, 6, and -3.

The compiler can infer the size of our array at compile time because of our array initializer. We can also specify it explicity:

```cpp
// This array has exactly 3 elements.
int[3] array = [1, 6, -3];
```

An explicit fixed-size array initializer must contain exactly that many elements. Too many or too few is a compile error:

```cpp
// This will error
int[3] array = [1, 6, -3, 4];
// This will work
int[3] array = [1, 6, -3];
// This will also error
int[3] array = [1, 6];
```
