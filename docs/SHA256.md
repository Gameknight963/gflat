# SHA-256 byte digests

`std::SHA256` incrementally hashes counted bytes using ordinary inline value
state. Include `core/SHA256.gf` and `core/BitOperations.gf`; it needs no allocator,
String, GC, or exception definitions. The algorithm follows
[RFC 6234 sections 4-6](https://www.rfc-editor.org/rfc/rfc6234/).

```csharp
using std;

int main()
{
    SHA256 hash = new();
    if (!hash.TryAppend("abc", 3)) return 1;
    byte[32] digest = hash.GetHash();
    if (digest[0] != (byte)0xba || digest[31] != (byte)0xad) return 2;
    return 0;
}
```

## State and snapshots

- Construction and `Reset()` start an empty message.
- `TryAppend(readonly(char)* data, nuint count)` consumes exactly the selected
  bytes, including NUL and non-ASCII values. Input chunk boundaries do not affect
  the resulting digest. No pointer is retained, so consumed input can be reused.
- `GetHash()` returns the 32 digest bytes in SHA-256's defined big-endian word
  order. Its fixed buffer is an ordinary value: the caller owns an independent
  copy without a heap allocation or disposal operation.
- Getting a digest does not consume or finalize the original state. Repeated
  calls return the same value, and further appends continue the message.
- Copying the hasher copies its complete running state. Copies can continue with
  independent suffixes. `GetHash` also works through an immutable view.

The largest accepted byte length is `2^61 - 1` (2305843009213693951), satisfying
SHA-256's message length limit of fewer than `2^64` bits. An append that would
exceed it returns false before reading input or changing any state. A zero count
succeeds without reading its input pointer. Callers supply readable live storage
for every accepted nonzero count, separate from the hasher's own state. Mutation
through aliases or simultaneous use of the same state is unsupported.

All operations are `nothrow` and use no internal heap allocation. State includes
one pending 64-byte block; block processing uses a fixed 64-word stack schedule.
`GetHash` snapshots that bounded state and adds padding only to the snapshot.

This is a scalar file/content digest API. It does not implement HMAC, password
hashing, keyed authentication, hardware acceleration, or a file IO policy. Use
existing `Hex` routines to encode the digest when text is needed.

Standalone Windows x64 object builds at O0 and O2 have no undefined symbols.
The corresponding executables also run with `-nostdlib` and `/NODEFAULTLIB`;
their only import is `KERNEL32.dll!ExitProcess`, used by the test startup.
These checks establish that result for the inspected target and build settings,
not a promise about backend-generated helpers on every platform. The shared
freestanding regression is configured for Windows and Linux x64 CI.
