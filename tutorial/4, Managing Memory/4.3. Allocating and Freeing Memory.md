# Allocating and Freeing Memory

Sometimes, you might want an array of a dynamic size, or to return a unique pointer on each function call.

<details>
<summary>The stack and the heap</summary>

We can do that by allocating memory on the heap.

Many programming languages don’t require you to think about the stack and the heap very often. But in a systems programming language like G♭, whether something is on the stack or the heap affects what you do with that memory.

Both the stack and the heap are "memory," but they are structured in different ways. 

The stack is managed via dedicated instructions such as `push` and `pop`, and stores values in the order it gets them. It's like our stack of books from eariler: you can stack books on top of each other, and remove them in the opposite order. This is referred to as last in, first out (LIFO). 

The heap is less organized: you request memory from the operating system, and it gives you memory... somewhere, floating above the stack.

Flip that model upside-down and you have an accurate representation of how the stack and the heap interact (the stack grows downwards, not upwards).

Using the stack is generally faster than using the heap. Pushing to the stack is a single CPU instruction (`push`), and `alloca` (allocate memory on the stack) in C is only several. Allocating memory is significantly more complicated. This is one reason why _allocation free_ libraries are championed in C and C++ (the other being they are much more portable).

The downside is that every stack allocation must not change size, since it is in a continous block of memory. Making it "larger" would just mean overwriting whatver is above/below it. The heap is better suited for something that must grow and shrink at runtime (such as a Vector).

</details>
<br>

Take this example for instance:

Filename: static_storage.gf
```cpp
int* GetPointer()
{
    static int number = 4;
    return &number;
}

int main()
{
    int* ptr1 = GetPointer();
    *ptr1 = 777;
    int* ptr2 = GetPointer();
    Console::WriteLine(ptr1);
    Console::WriteLine(ptr2);
    return 0;
}
```

```
$ gflat static_storage.gf --run

777
777
```

The pointee of `ptr2` changed when we dereferenced `ptr1`! That's because we returned the address of the same static variable, so they point to the same location in memory.

To fix this, we can _allocate memory_ on the heap. That can be done with `Memory::Allocate()`. It returns `void*?`, so we need to cast it before using it:

```cpp
int* GetPointer()
{
    return (int*)Memory::Allocate(sizeof(int));
}

int main()
{
    int* ptr1 = GetPointer();
    *ptr1 = 777;
    int* ptr2 = GetPointer();
    Console::WriteLine(ptr1);
    Console::WriteLine(ptr2);
    return 0;
}
```

```
$ gflat allocation.gf --run

777
0
```

Why was the second one zero? Well, we never set the memory in that allocation to anything, so it's whatever was there before. The OS wipes pages before giving them to you if they were used by another process previously for security reasons, so that could be one reason why it was 0.

This is also technically bad practice. If `Allocate()` returns null, that means the allocation failed. You should always check:

```cpp
int*? GetPointer()
{
    return (int*?)Memory::Allocate(sizeof(int));
}

int main()
{
    int*? ptr1 = GetPointer();
    if (ptr1 == null) return 1;
    *ptr1 = 777;
    int* ptr2 = GetPointer();
    if (ptr2 == null) return 1;
    Console::WriteLine(ptr1);
    Console::WriteLine(ptr2);
    return 0;
}
```

Later, we'll learn about exceptions, which can make code like this less repetitive.

This memory is also...

## Leaking.

Any memory allocated MUST be freed with `Memory::Free()`! Otherwise you get a _memory leak_: your program uses more and more memory until bad things happen (depending on your OS).

In this case, it's technically fine. We make two allocations before immediately exiting. The exit means the OS cleans any memory we allocated anyway.

But it's good practice to free the memory regardless:

```cpp
using Standard;

int*? GetPointer()
{
    return (int*?)Memory::Allocate(sizeof(int));
}

int main()
{
    int*? ptr1 = GetPointer();
    if (ptr1 == null) return 1;
    *ptr1 = 777;
    int* ptr2 = GetPointer();
    if (ptr2 == null) return 1;
    Console::WriteLine(ptr1);
    Console::WriteLine(ptr2);
    Memory::Free(ptr1);
    Memory::Free(ptr2);
    return 0;
}
```

Note that using `ptr` or `ptr2` are dangling after freeing them is dangling. Using it is undefined behavior, and will probably crash your program.
