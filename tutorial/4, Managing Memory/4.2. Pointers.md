## Pointers

A pointer is a variable whose value is an address: the location of something else in memory.

Filename: pointers.gf

```cpp
int main()
{
    int x = 4;
    int* ptr = &x;
    *ptr = 94023;
    Console::WriteLine(x);
    return 0;
}
```

```
$ gfc pointers.gf --run
94023
```

How did the value of `x` change if we never reassigned it? Let's go through that line by line:

```cpp
    int* ptr = &x;
```
This declares a _pointer_ to `x`. It's value is the address of `x` in memory.

```cpp
    *ptr = 94023;
```

This _dereferences_ the pointer, setting the value of it's _pointee_ (`x`) to 94023.

### Still not making sense?

That's fair. It's a pretty difficult concept to grasp. Let's try it with an analogy instead.

Imagine a big library, except that library only has one bookshelf, and that bookshelf is a single line of books alongside each other.

Let's say the value of `x` is stored in a book titled "x" somewhere in that bookshelf. Then, we note of it's location in another book titled "ptr" and put that some other location. That second book is essentially a pointer.

Then, later, we can take the "ptr" book, read it's value, go to the corresponding book, open it, and change it to say whatever we want (or even replace it with another book). We've just "dereferenced" our "pointer!"

If we wanted, we could even make note of where we put our "ptr" book, and have a pointer to a pointer!

Still not making sense? That's fine. Look it up on Youtube, perhaps chat with someone knowledgeable, ask an LLM, or try taking a break if it feels too hard.

This is a very essential concept to understand; much of the tutorial builts on pointers, so you'll be lost if you don't get it.

## `readonly` pointers

You might want to protect the value of the pointee, so others can't modify it. Your first instinct coming from C++ might be to do this:

Filename: pointers.gf

```cpp
int main()
{
    int x = 4;
    readonly int* ptr = &x;
    *ptr = 94023;
    Console::WriteLine(x);
    return 0;
}
```

But this actually compiles and runs the same!

```
$ gfc pointers.gf --run
94023
```

In this case, `readonly` only protects the value of the pointer itself, not the value of the pointee. If you want to protect the pointee, you can do that like so:

```cpp
int main()
{
    int x = 4;
    readonly(int)* ptr = &x;
    *ptr = 94023; // Error
    Console::WriteLine(x);
    return 0;
}
```

This will no longer compile since we try to reassign the readonly pointee.

## Nullable pointers

Sometimes, a pointer can point to address '0'. This represents a _null_ pointer.

If you try to dereference a null pointer, that is undefined behavior and will usually crash your program.

In C and C++, there is no distinction between a pointer which may be null and one that might not.

In G♭, there is. A non-nullable pointer is the one we just used:

```cpp
int x = 4;
int* ptr = &x; // int* means non-null
*ptr = 94023;
```

If you want to express nullable intent, you can use `T*?`.

```cpp
int x = 4;
int*? ptr = &x;
*ptr = 94023;
```

The compiler will not let you dereference a nullable pointer without checking if it is null first. In this case, it knows the pointer is not null, since we just assigned it with a valid address. Here's an example where we must check:

```cpp
int number = 4;

int*? GetPointer()
{
    return &number;
}

int main()
{
    int*? ptr = GetPointer();
    *ptr = 94023; // error
    return 0;
}
```

The compiler will not compile this! `GetPointer()` returns a pointer which may be null, so dereferencing it is unsafe!

We can get around this safely by checking if it is null first:

```cpp
int number = 4;

int*? GetPointer()
{
    return &number;
}

int main()
{
    int*? ptr = GetPointer();
    if (ptr == null) return 1;
    // The pointer cannot be null past this point.
    *ptr = 94023;
    return 0;
}
```

We can also use the _bang_ operator (`!`) to tell the compiler to shut up instead. Only use this if you're sure it's safe.

```cpp
int number = 4;

int*? GetPointer()
{
    return &number;
}

int main()
{
    int*? ptr = GetPointer();
    int* nonNull = ptr!;
    *nonNull = 24;
    return 0;
}
```

This specific code block is 100% safe, but the better option would've been to make `GetPointer()` return `int*` instead of `int*?`.

Note that at runtime, nullable and non-nullable pointers are the same. The concept simply doesn't exist at runtime. So, if you mess around with memory in dumb ways, you might be able to  make a non-nullable pointer null even if you didn't use the `!` operator.

## Returning pointers from a function

One thing someone new to a manually managed language might do is this:

Filename: pointers.gf

```cpp
int* GetPointer()
{
    int number = 4;
    return &number;
}

int main()
{
    int* ptr = GetPointer();
    *ptr = 94023;
    return 0;
}
```

Returning the address of a local is not smart. _Dereferencing_ the retured address of a local is undefined behavior and should never be done!

After `GetPointer()` returns, the returned pointer is _dangling_. Here's why:

1. number lives in GetPointer's stack frame — a slot on the stack.
2. `return &number;` copies that slot's address out as a number. Fine so far.
3. But `return` also tears down GetPointer's frame. `number` ceases to exist. The address is now a souvenir, it points at a slot that no longer belongs to anything.
4. `*ptr = 94023;` writes 94023 into that dead slot.

So if we run this code, it's surely going to segfault, right?

```
$ gfc pointers.gf --run

$
```

...?

Let's print the pointee to see what's going on:

```cpp
int* GetPointer()
{
    int number = 4;
    return &number;
}

int main()
{
    int* ptr = GetPointer();
    *ptr = 94023;
    Console::WriteLine(*ptr);
    return 0;
}
```

```
$ gfc pointers.gf --run
94023
```

So... did I lie to you? No. That's what makes this bug so insidious - if you kept writing code like this, you would eventually get a genuinely horrible to debug crash. The fact that it works sometimes is what trips up beginners. Luckily I learned about the dangers before I ever had the chance to write code like this, and hopefully now you did too.

Since it's undefined behavior, it also means the optimizer can do whatever it wants with it. Sometimes it assumes undefined behavior can't happen and just deletes `*ptr = 94023;`. Now, if you compile with `--optimization 2`, it might print something completely nonsensical such as the original value of 4.

One reason it might "work" is that tearing down a stack frame doesn’t usually reset its values. The next call may overwrite them. So, the value at the address stored in `ptr` might be left unchanged, letting us read and write to it as if nothing was wrong.

## Returning pointers from a function (safely)

Two ways to do this are using a global variable and allocating memory. We'll dicuss the first here; the second in section 4.3.

You may notice in my earlier examples, I returned the address of a global rather than a local:

```cpp
int number = 4;

int* GetPointer()
{
    return &number;
}

int main()
{
    int*? ptr = GetPointer();
    *ptr = 94023;
    return 0;
}
```

This code is **100% safe**. `number`, being a global, has static storage duration, meaning it lasts for the lifetime of the program.

```cpp
int* GetPointer()
{
    static int number = 4;
    return &number;
}

int main()
{
    int*? ptr = GetPointer();
    *ptr = 94023;
    return 0;
}
```

Slightly counterintuatively, this is also safe. Within a function, the `static` keyword gives `number` static storage duration, so it also lasts for the lifetime of the program.

As a consequense, the value of `number` is kept between calls:

Filename: static_storage.gf

```cpp
int GetNumber()
{
    static int number = 4;
    return ++number;
}

int main()
{
    Console::WriteLine(GetNumber());
    Console::WriteLine(GetNumber());
    Console::WriteLine(GetNumber());
    return 0;
}
```

```
$ gfc static_storage.gf --run
5
6
7
```

### `void*`

Does this function return a value?

```cpp
void* GetPointer()
{
    static int number = 4;
    return &number;
}
```

Yes, it returns `void*` - a pointer to memory of an unknown type. `void*` is distinct from `void` (the latter means no value whatsoever). To use it, we must cast it to a known type:

Filename: voidstar.gf

```cpp
int main()
{
    int* ptr = (int*)GetPointer();
    Console::WriteLine(*ptr);
    return 0;
}

void* GetPointer()
{
    static int number = 4;
    return &number;
}
```

```
$ gfc voidstar.gf --run
4
```

> [!WARNING]
> Casting pointers is not a safe operation and assumes you know what you are doing! If you get it wrong, you can interpret garbage memory, resulting in unexpected behavior or a crash.
