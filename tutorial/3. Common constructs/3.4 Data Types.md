# Data Types

Every variable in G♭ is always of a certain _type_. A _type_ tells the G♭ what type of data is inside that variable, so that it knows how to work with that data.

Types are annotated by putting the type name in front of the variable separated by a space.


```cpp
int GetSomething()
{
    return 7;
}
int main()
{
    int x = GetSomething();
    return 0;
}
```

You can also skip having to annotate the type by using _type inference_, by putting the `var` keyword in place of the type.

I would only recommend using this in select situations:
 1. You have a really long type name
 2. The type is obvious and redundant
 3. You're abusing the type system in some way and not using `var` makes everything annoying

```cs
int main()
{
    // huh? what type does GetSomething() return??
    // Now I have to go look at the delaration...
    var x = GetSomething();
    return 0;
}
```

Type inference actually _reduced_ the readability of this code. In advanced G♭, there are some cases where it really helps though.

To some people, types are a thing to work around, and that's how some languages like Rust and TypeScript ended up relying heavily on inference. I don't think that's a good mindset: types matter very much for low-level code, since they directly affect what your program is doing. Imagine thinking you're working with a `char` and actually working with an `int`! Since they matter so much, it feels like a strange descision to try to push them out of the syntax as much as possible.

### Scalar Types

A scalar type represents a single value. Here are four categories used in G♭:
 - floating-point numbers,
 - integers,
 - booleans,
 - and characters.

 You may recognize these from other programming languages. Let's jump into how G♭ handles them.

| Size          | Signed      | Unsigned         |
| ---           | ---         | ---              |
| 8-bit         | `sbyte` or `char` | `byte`        |
| 16-bit        | `short`     | `ushort`         |
| 32-bit        | `int`       | `uint`           |
| 64-bit        | `long`      | `ulong`          |
| 128-bit       | `extralong` | Not available    |
| Platform-size | `nint`      | `nuint`          |

> Note: I'll probably rename `extralong` to `longlong` in the near future so it sounds less dumb

Unlike C++, G♭ guarantees these exact sizes.

`nint` and `nuint` are pointer-sized. The currently supported Windows x64 and Linux x64 targets use 64 bits for both.

Some of these can be expressed explicitly with literals as shown below. Literals are also useful if you want your number in a different format (hexadecimal, character, binary...):

| Literal   | Example  |
| ---       | ---      |
| Decimal   | `9843`   |
| `long`    | `9843l`  |
| `ulong`   | `9843ul` |
| Hex       | `0x4b23f`|
| Octal	    | `0o77`   |
| Binary    | `0b00101`|
| `char`    | `'A'`    |
| `bool`    | `true`   |

So how do you know which type of integer to use? If you’re unsure, `int` is probably fine (that's why it has the most generic name).

The primary situation in which you’d use `nint` or `nuint` is when indexing some sort of collection.

### Floating-Point Types

G♭ also has two floating-point types: `float` and `double`:

```cpp
int main()
{
    float f32 = 2.0f;
    double f64 = 3.0;
    return 0;
}
```

### Numeric operations

G♭ supports all the operations you'd expect for all the aforementioned number types: addition, subtraction, multiplication, division, and modulus.

Integer division truncates toward zero.

The following code shows how you'd use each operation:

```cpp
int main() {
    // addition
    int sum = 5 + 10; // 15

    // subtraction
    float difference = 95.5f - 4.3f; // 91.2

    // multiplication
    int product = 4 * 30; // 120

    // division
    double quotient = 56.7 / 32.2; // 1.76086956522
    int truncated = -5 / 3; // -1

    // remainder/modulus
    int remainder = 43 % 5; // 3

    return 0;
}
```

### Booleans

A boolean is a one-byte value that has one of two values: `true` or `false`. To declare a boolean, use `bool`:

```cpp
int main()
{
    bool t = true;
    return 0;
}
```

The primary way to use booleans is through conditionals such as the `if` expression, which will be discused in section 3.7.

### The character

A `char` is a one-byte value. It can hold ASCII characters, but not Unicode characters that need more than one UTF-8 byte.

```cpp
int main()
{
    char A = 'A'; // allowed
    char fih = '🐠'; // Compile error: more than one UTF-8 byte
    return 0;
}
```

> This section needs to be updated with the information on what happens if you _do_ try to do that.

String literals are just an array of characters:

```cpp
int main()
{
    // points to the first element of the array
    readonly(char)* string = "c string!";
    Console::WriteLine(string);
    return 0;
}
```

We'll learn more about arrays in section 4.1.

> Yes, this is a C string. Yes, it's null terminated. You have Dennis Ritchie to blame, not me. I didn't want to have 999 types of strings like Rust.

A string can contain several UTF-8 bytes per character, so this is allowed:

```cpp
int main()
{
    // '♭' is a unicode character
    readonly(char)* string = "G♭";
    return 0;
}
```

This uses UTF-8 encoding, which will be discussed in a future secction. The resulting string would be 5 bytes long (four, plus the null terminator).

## Bypassing the type system with casts

Sometimes, you want to switch between different types of numbers, or reinterpret the underlying bits of those numbers as something else.

You can do that with casts. There are two types of casts in G♭: c-style casts, and `reinterpret`:

Filename: casts.gf

```cpp
int main()
{
    int number = 94;
    char carat = number.reinterpret<ref readonly(char)>();
    ushort smaller = (ushort)94;
    Console::WriteLine(carat);
    Console::WriteLine(smaller);
    return 0;
}
```

> If you have a big-endian machine for whatever reason, you might not get the same results

```
$ gfc casts.gf --run
^
94
```

`reinterpret<ref readonly(char)>()` reads the first byte of `number` as a character. It is a dangerous operation when used on complex types, often producing garbage data. In this case, the result depends on endianness.

> Read more on endianness on the [Wikepedia page](https://en.wikipedia.org/wiki/Endianness).

C-style casts convert values. Widening an integer preserves its value and produces a larger representation:

```cpp
int number = 94;
long wider = (long)number;
```

Note that since we're converting to a wider type, an explicit cast is not necessary here. If dropped, the conversion will be made implcitly.

If you're converting between signed and unsigned types, you need an explicit cast. This is sometimes _not_ the same thing as reinterpreting; the bit pattern might change.

Casting a negative 32-bit integer to `uint` wraps it around to a positive value with the same bits:

Filename: unsigned_conversions.gf

```cpp
int main()
{
    int number = -94;
    uint converted = (uint)number;
    uint reinterpreted = number.reinterpret<ref readonly(uint)>();
    Console::WriteLine(converted);
    Console::WriteLine(reinterpreted);
    return 0;
}
```

```
$ gfc unsigned_conversions.gf --run
4294967202
4294967202
```
