# Hello, World!

## Directory setup

I'd recommend creating a 'projects' directory in your home directory. You're free to organize your files however you prefer obviously.

```
$ mkdir ~/projects
$ cd ~/projects
$ mkdir "hello world"
$ cd "hello world"
```

## G♭ program basics

G♭ program files always end with the '.gf' extension.  If you’re using more than one word in your filename, the convention is to use an underscore to separate them. For example, use _hello_world.gf_ rather than _helloworld.gf_.

There are other types of naming conventions for different types of files, which will be discussed in a later section.

Filename: main.gf

```cpp
int main()
{
    Console::WriteLine("Hello World!");
    return 0;
}
```

After saving this file, return to your terminal window. Compile and run your program like this:
```
$ gflat main.gf --run
Hello, world!
```

If that last line 'Hello, world!' did in fact appear, congratulations! If not, open an issue right away because that's not meant to happen!

## What's happening here?

Let's pick apart each piece of this program in detail:

```cpp
int main()
{

}
```

This defines a function called `main` which returns `int` in the global scope. The `main` function is special: it is the "entry point" of your program, meaning it's where the first code actually runs. 

The body of the function holds the following code:

```cpp
Console::WriteLine("Hello World!");
return 0;
```

First, the program calls the function `WriteLine` in the namespace `Console`. Namespaces are simply a container used to organize items and keep their names unique so they do not clash.

Second, you see the "Hello World!" string. This is a _parameter_ or _argument_ passed to the `WriteLine` function. `WriteLine` is a function from the Standard library which uses it to print that string to the console. 

Third, we end the line with a semicolon (`;`). This indicates that this statement is over, and the next one is ready to begin.

Finally, we notice the "`return 0`" at the end of a function. A return value is the output a function sends back to the part of the code that called it once it finishes running. Similarly, this line also ends with a semicolon.

The return value of `main` is the _exit code_, which is a special number identifying why the program exited. It can be anything you want, but in general, 0 means "sucessful" and 1 means "unsucessful."

On Linux, this code may be from 0-255. Inspect it like this:

```
$ echo $?
```

On Windows, it can be any 32-bit integer, ranging from -2,147,483,648 to 2,147,483,647. You can inspect the exit code like this:

```
> echo %ERRORLEVEL%
```

## Compilation and Execution

```
$ gflat main.gf --run
```

This tells the G♭ compiler to _compile_ your program and _run_ your the resulting executable.

You can also run these equivalant commands:

```
$ gflat main.gf
$ ./main
```

If you've previously programmed in C or C++, you’ll notice that this is similar to `gcc` or `clang`. After compiling the program sucessfuly, the G♭ compiler emits a binary executable.

You can see this executable by running `ls`:

```
$ ls
main  main.gf
```

If you're more familiar with dynamic languages such as Ruby or JavaScript, you might not be used to compiling and running your program being separate steps. The G♭ compiler produces an actual executable which anyone can run without needing the G♭ compiler installed. If you give someone a _.rb_ or _.js_ file, they'll need to have a Ruby or JavaScript interpreter installed (respectively).

Compiling individual source files is fine for small files like these, but for larger, real-world applications, you'll probably want to use the project system, which we'll talk about next.
