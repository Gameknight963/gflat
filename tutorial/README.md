# The G♭ Programming Language

Welcome to "The G♭ Programming Language." If reading through pages of unsorted documentation isn't
your style, then you're in the right place. This tutorial aims to provide a _sequential, readable_ collection of knowledge.

I made G♭ out of my frustration with the lack of control C# gives you,
but also out of my frustration of how confusing modern C++ is.
Not to mention my immense dissatisfaction with Rust. Here's a rant about Rust
which I more or less agree with: https://dorinlazar.ro/240228-i-hate-rust-programming-language/

My aim is to make an experience that combines both the high-level convenience of C#, with the control C++ gives you: high level when you want it to, low-level otherwise, with a bunch of compile-time constructs bridging that gap.

If you agree with anything I said, then G♭ might be worth trying. Read a few pages from here and see if it suits you.

This tutorial assumes you have some programming experience in another language. If you're new to programming in general, you should consider an introductory tutorial to a language like C#. I actually _wouldn't_ encourage Python as a first language (as many do) since it teaches you very bad habits and tends to create unreadable codebases.

This tutorial is still under construction! You will not be able to complete it.
It also does not currently provide any explanation on how to _install_ G♭ itself. 

Once you complete this tutorial (when tutorial itself is complete), you will have made:
 - The obligitory Hello World program
 - A simple number guessing game!
 - A command-line to-do list.
 - A small subset of curl.

 ## How to use this tutorial

 Each folder represents a _chapter_. Go from folder to folder sequentially, in order of it's number.

 A folder might contain several things:

   1. A single README.md file
   2. Many Markdown files representing different _sections_, numbered similarly with chapters but with a decimal point
   3. Both 1 and 2
   4. An optional SUMMARY.md

In the first case, that single file is the entire chapter.

In the second, read through each file in order of it's section.

In the third, the README.md represents a summary/overview of the chapter. Read it first, then read the rest of the files.

If a SUMMARY.md is present, it should be read after every other file has been read. It will go over what you've learned, and next steps, such as programs to exersize the skills you learned.
